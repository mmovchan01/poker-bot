# Покерный анализатор для локального симулятора

```text
poker-bot/
├── poker_bot/
│   ├── __init__.py
│   ├── __main__.py       # цикл и контроль повторных действий
│   ├── config.py         # конфигурация и ROI
│   ├── models.py         # структуры состояния
│   ├── vision.py         # MSS, YOLO, OpenCV, EasyOCR и стабилизация
│   ├── solver.py         # тиры и Monte Carlo/treys
│   ├── history.py        # SQLite и CSV
│   └── control.py        # динамические клики
├── tests/
├── config.example.json
├── data.yaml
├── requirements.txt
└── README.md
```

Python 3.10+, графический рабочий стол с доступом к экрану и устройствам ввода. Поддерживаются только принадлежащие пользователю локальные симуляторы с виртуальными фишками. Модель и конфигурация привязаны к конкретному интерфейсу; стандартные веса COCO **не распознают** эти классы.

## Установка и запуск

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp config.example.json config.json
python -m poker_bot --config config.json
```

Первый запуск EasyOCR может скачать веса; подготовьте их заранее при отсутствии интернета. На Linux PyAutoGUI требует работающий X11 и доступный DISPLAY; Wayland и удалённые рабочие столы могут блокировать захват или управление. PyAutoGUI FAILSAFE включён по умолчанию: переместите указатель в угол экрана для аварийной остановки; также доступен Ctrl+C. Для кликов установите `dry_run: false` **только после** проверки распознавания. Работайте на одном мониторе с согласованным DPI и разрешением.

`window` — `[left, top, width, height]` в пикселях виртуального экрана; координаты задаются вручную и не отслеживают перемещение/изменение окна. При изменении размеров обновите их. OCR ROI `[x, y, width, height]` и вертикальные диапазоны зон карт задаются долями окна 0–1. Примеры координат не являются универсальными: настройте их по скриншоту. Светлая маска HSV рассчитана на светлый малонасыщенный текст; при другой цветовой схеме подберите пороги в `vision.py`. Каждый ROI должен содержать ровно одну сумму, включая явно отображаемый ноль стоимости чека. Поддерживаются `1.5K`, `25K`, `2.4M`, десятичная запятая и распространённые разделители тысяч; неоднозначное `1,500` без суффикса трактуется как 1500.

## Датасет и модель

Разметьте снимки конкретного симулятора в YOLO-формате с индексами из `data.yaml`, разбейте на `datasets/poker/images/{train,val}` и `datasets/poker/labels/{train,val}`. Класс карты — отдельный видимый уголок: ранг `2..9,T,J,Q,K,A`, масть `c,d,h,s`. Два уголка одной карты объединяются по имени в одной зоне, одинаковые карты в разных зонах вызывают отказ. Поэтому ошибочное распознавание может скрыть карту; обучайте модель на перекрытиях, бликах и анимации.

`opp_cards` размечается **одним прямоугольником на место активного соперника**, охватывающим обе рубашки; подсчёт отдельных рубашек или скрытые/загораживаемые места недопустимы. Дилер выводится как рамка, но позиция относительно мест не определяется: для неё нужна схема мест конкретного стола. `bet_input` — поле ввода общей суммы ставки; без него рейз не предлагается. Интерфейс должен принимать ввод Ctrl+A и десятичное число с точкой. Нет проверки минимального рейза или правил ввода конкретного симулятора; перед включением кликов проверьте их вручную. Если банком или стеком управляет другая логика (например сумма рейза обозначает добавку), не включайте автоматизацию.

```bash
yolo detect train model=yolov8n.pt data=data.yaml epochs=100 imgsz=640
mkdir -p weights
cp runs/detect/train/weights/best.pt weights/best.pt
```

## Работа и ограничения

Три совпадающих кадра с интервалом 150 мс обязательны; совпадают карты, суммы, количество соперников и набор кнопок. Неизвестные/неполные данные не приводят к действию. После расчёта стол проверяется ещё раз; физическое изменение интерфейса в момент клика исключить нельзя. Для уменьшения повторных кликов одинаковое состояние обрабатывается один раз до исчезновения кнопок или изменения состояния. Графический интерфейс должен быть видимым и не перекрытым.

Префлоп использует эвристические тиры, не полноценную стратегию. Постфлоп — статистическая оценка equity (не точное значение), равномерные случайные диапазоны соперников, с разделением ничьей. Пот-оддсы не учитывают рейк, side pots и будущие ставки; рейз — эвристика, а не доказанный +EV. В частности, результаты не предназначены для игры на реальные деньги.

`poker_history.db` содержит `hands` и `decisions`; `hands_log.csv` содержит решения, в том числе пробные и записанные до попытки клика. Профит фиксируется при появлении других карманных карт как разница стеков в первые наблюдаемые моменты хода. Это оценка: блайнды, пополнения, пропущенные раздачи и позднее обнаружение искажают её. Две последовательные раздачи с теми же картами неразличимы по одному изменению карт; последняя раздача остаётся незакрытой при выходе. История текущей раздачи не восстанавливается после перезапуска. Для надёжного учёта требуется отдельный сигнал начала раздачи и снимок стека до блайндов.

Тесты: `python -m unittest discover -s tests -v`.

## Быстрые снимки окна для настройки

В Windows установите зависимость и запустите скрипт:

```powershell
python -m pip install mss
python tools/capture_screens.py
```

Переключитесь в игру и нажимайте **F8** для снимка всего первого монитора; **F9** завершает программу. Не закрывайте терминал во время работы. Снимки PNG без изменения разрешения сохраняются в `screenshots/` относительно текущей папки. Для другого монитора используйте `--monitor 2`, для другой папки — `--output путь`. Координаты монитора записываются в `screenshots/capture_region.json`. Программа не отправляет файлы в сеть.

Скрипт использует глобальные горячие клавиши Windows. Если F8 или F9 уже заняты, освободите их и перезапустите скрипт. Если игра перехватывает клавиши или снимки получаются чёрными в эксклюзивном полноэкранном режиме, попробуйте безрамочный оконный режим. Уведомления и другие видимые элементы также попадут на снимок; проверьте отсутствие личных данных перед отправкой.

### Windows: отдельный EXE на C++

В `tools/windows_capture/` находится нативная утилита, не требующая Python при использовании. Собрать её можно на Windows с Visual Studio 2022 или бесплатными Visual Studio Build Tools и компонентом «Разработка классических приложений на C++»:

1. Откройте **x64 Native Tools Command Prompt for VS 2022**.
2. Выполните `путь\к\проекту\tools\windows_capture\build.bat`.
3. Запустите созданный `tools\windows_capture\GameCapture.exe`, выберите номер окна в списке и переключитесь в игру.
4. **F8** сохраняет PNG в папку `screenshots` рядом с EXE, **F9** завершает программу. Можно закрыть консольное окно. Программу и её папку можно скопировать в другое доступное для записи место на Windows.

Утилита снимает видимые пиксели прямоугольника выбранного окна вместе с рамкой, автоматически отслеживая его положение и размер. Окно должно быть развёрнуто, находиться на экране и не перекрываться другими окнами; уведомления, перекрывающие окно, попадут в кадр. В некоторых играх с защищённым или эксклюзивным полноэкранным режимом захват экрана может быть чёрным; попробуйте оконный режим. Проверьте файлы перед отправкой на наличие личных данных. Если F8 или F9 заняты, закройте использующую их программу. EXE не отправляет данные в интернет.
